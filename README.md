# AI Radar — 每日 AI 情报系统

目标：每天不用刷 Twitter/HN/公众号，5 分钟读完一份**已经替你筛选并判断过**的情报。

## 桌面应用（日常入口）

双击 `bin\AI 情报台.exe` 就能开（可以右键「发送到 → 桌面快捷方式」）。应用就是这套系统的界面壳。
第一次打开会有三步引导：填一个兼容 OpenAI 的模型 key（可跳过）、说一句你在做什么、看今天的三条。
应用自带运行环境，不用另装 Node.js；只有想用 Windows 计划任务跑 `run_daily.cmd` 时才需要本机装 Node。

**界面布局**（2026-10-25 改版）：顶上一条深色命令栏，写着现在在哪一页，右边是「搜索全部记录」和深浅色切换；
左栏上半是今天的日期和采集读数（最后采集时间、数据源正常数、项目数、新闻数）和「重新采集」，
下半是 12 个入口，按用途分三组，外加设置：

| 组 | 入口 |
| --- | --- |
| 阅读 | 01 今日简报 · 02 周报 · 03 历史 · 04 收藏 |
| 发现 | 05 需求雷达 · 06 原始雷达 · 07 扩展能力 |
| 工具 | 08 对话 · 09 模板库 · 10 概念词典 · 11 安装 agent |
| — | 12 设置 |

深浅色默认跟随系统，点命令栏的「深色 / 浅色」后会记住（存在窗口的本地存储里）。

**任务进度卡片**：采集、生成简报、对话、模板生成、周报、摘要、需求筛选、GitHub 现搜、追踪检查、领域包、简报译英文、
历史档案这些要等的操作，右下角会出一张卡片：一个小人动画，外圈一行 LOADING 绕着转；下面是 24 格进度条、
当前在做哪一步、已用时间，以及「多久没有新动静」。
- 采集有真实进度：采集器每抓完一个源打一行 `[radar] step 3/12 新闻`，卡片按 12 步走。
- 会持续报告的任务（采集、档案、流式回答）超过 30–45 秒没有新动静，最后一行变成黄底「可能卡住了」；
  只能等返回的任务（生成简报、周报等）超过平时两倍时间，提示「比平时慢」。
- 完成后外圈停转、字变成 COMPLETE，2.5 秒后自己收起；出错时字变成 ERROR，卡片留着显示原因，点「关掉」才消失。
- 点「收起」变成右下角一个小条（显示百分比和已用时间），任务照常在后台跑，点小条再展开。
- 代码在 `app/renderer/jobs.js`，动画图在 `app/renderer/assets/loading/`（来源见同目录 `SOURCE.txt`）。

**自动更新**：应用启动 15 秒后和每 6 小时，去 GitHub Releases 读一次 `latest.json` 比版本号（设置里可以关）。
有新版本时，命令栏出现黄色的「新版本 vX」，设置的「更新」一栏能看说明、点「下载更新」（进度显示在任务卡片里），
下载好后点「重启并更新」。
- 只换程序代码（`bin\resources\app`）和随应用发布的脚本、模板、词典、提示词，不动 Electron 运行环境；
  `app/config.json`、`state/`、`data/`、`digests/`、`inbox/`、`chats/`、`local/` 都不碰。
- 模板、词典、提示词这类数据文件，用户改过的不覆盖，新版另存成同名的 `.new` 文件，重启后会提示是哪几个。
  判断依据是 `release/history.json` 里记的每个文件历次发布过的 sha256。
- 整个更新包和里面每个文件都校验 sha256，对不上就丢弃；被替换的旧文件备份在用户数据目录的 `update\backup-*`。
- 有 `.git` 的目录（开发目录）和没打包的开发运行不会自动更新，用 git 管理。
- 新版本如果要求更新的 Electron 运行环境，只提示去下载完整版，不自己换。
- 国内连不上 GitHub 时，可以把同样的 `latest.json` 和更新包放到镜像，在 `app/config.json` 里加
  `"updateFeeds": ["https://镜像地址/目录"]`，会先试镜像再试 GitHub。

**本机覆盖（`local/`）**：`local/` 下放同名文件就优先用它，例如 `local/prompts/daily.md`、`local/templates.json`、
`local/concepts.json`。适合放写着自己项目、设备的个人版本；`local/` 不进仓库，更新也不碰。

**发布新版本**（维护者）：
1. 改 `app/package.json` 的 `version`，在 `release/notes/<版本>.md` 写更新说明，提交。
2. `node app/tools/release.mjs`：从已提交的内容打更新包，产出在 `release/out/<版本>/`。
   如果 `local/release-forbid.txt` 存在，里面列的词出现在要发布的文件里就会中止（防止把个人内容发出去）。
   加 `--dist <空目录> --zip` 还会导出一份给新用户的完整目录并压成 zip。
3. 提交 `release/history.json`，在 GitHub 上建 Release（标签 `v<版本>`），把 `latest.json` 和更新包（以及 zip）传上去。
   具体步骤写在 `release/out/<版本>/发布步骤.txt`。

外观规则写在 `app/renderer/styles.css` 开头：黄色只表示「当前位置 / 可以点 / 要看一眼」，切角的块可以点，红色只留给删除。
界面字体 Saira（SIL OFL 1.1，许可证在 `app/renderer/assets/fonts/Saira-OFL.txt`）随应用打包，中文用系统的 Noto Sans SC，没有就用微软雅黑。
改版前的界面文件备份在 `app/backups/ui-endfield-20261025/`。

各入口：

- **今日简报** —— 就是 `digests/<今天>.md`，大字引言 + 分节阅读，左缘有一条滚动进度轴
- **需求雷达** —— 把想要的东西记成一条需求（目标、常用软件、预算、设备、难度、试过什么），按条件筛项目，并在理由里直接写出对不上的地方；「现在帮我找」「持续帮我关注」「早期发现」都在这一页（见「需求雷达」）
- **扩展能力** —— 插件 / 技能 / MCP 的统一目录：按四类用途挑，按你机器上装了什么筛，每张卡片写清在哪用、收不收费、要什么权限、怎么开始、最近核实过，并分开标「目录收录 / 作者宣称 / 实测过」（见「扩展能力」）
- **模板库** —— 10 个填空就用的提示词模板（写周报 / 读文章 / 改简历 …），首页顶部也有入口
- **翻译（并入雷达）** —— 不再是单独一栏：雷达每行有「中」按钮点一下译成中文，顶上还有「译这一栏」批量译当前标签页的前 8 条，
  简报工具栏可以整篇译成英文；长文翻译还留在「设置 → 翻译长文」里（见「翻译」）
- **概念词典** —— 按词典用：搜词、打开单独一页、Esc 返回；69 个核心词分八组，另加音乐制作 / 游戏美术·像素 / 数据分析三个领域包（含工具与网站），也能让模型现写一个新领域（见「概念词典」）
- **对话** —— 用你自己填的 API 直接问，它会记住你的项目和需求（见「对话、需求记忆与猜你需要」）
- **原始雷达** —— 采集器原样输出，10 个标签页：前沿 / 新星 / 高星活跃 / AI 项目 / 技能 / 模型 / 新闻 / 论文 / HN / 社区，
  「前沿」是三层阅读（今天值得知道 / 本周能力变化 / 深入了解，见「前沿动态」），
  下面还有一排**时间范围**（见「按时间回看」）
- **历史** —— 按天翻，带一行摘要
- **周报** —— 最近 7 天的收口：真正变了什么、今晚能做什么（见「给零基础用的那几层」）
- **收藏** —— 你点过 ★ 的条目（`state/bookmarks.json`），以及「关注后续」记下的条目（`state/followups.json`）
- **安装 agent** —— 23 个主流 agent 的安装方式，按形态分组（见「安装 agent」）
- **技能说明书** —— 技能栏每条都能点开看：能做什么、本机能不能用、怎么装、装好没、怎么卸（见「技能说明书」）
- **设置** —— API 地址、模型、key（带「测一下」）、每天自动采集、猜你需要、推送提醒、AI 摘要、
  花费估算、历史档案、重新看引导
- **搜索** —— 命令栏「搜索全部记录」（或 `Ctrl+K` / `/`），跨所有天的项目 / 模型 / 新闻 / 论文 / B站 / 知乎 / 简报正文 / agent 装法；
  浮层底部还有一行「在网络上搜」，能直接搜外网
- **这对我有什么用** —— 雷达每行点「有什么用」，四问 + 证据分级 + 试试看/关注后续（见「这对我有什么用」）
- **联网搜索** —— 采集器每天抓一轮中文实测，对话时也会先搜一次（Bing RSS，可关，见「联网搜索」）

除了左栏的「重新采集」，还有一个常驻入口：**托盘图标**。关掉窗口不退出，采集照跑；
托盘菜单里有「立即采集 / 打开数据文件夹 / 退出」。

三种跑法，按你当天的耐心选：

| 想干什么 | 怎么做 | 结果 |
| --- | --- | --- |
| 只更新原料 | 点「重新采集」（或等每天定时） | `data/` `inbox/` 更新，0 token |
| 让应用自己写简报 | 设置里填一个兼容 OpenAI 的 key，点「生成简报」 | 应用内带模型调用，直接出稿 |
| 让 DSH 里的 agent 写 | 点「复制指令给 DSH」，粘到对话框 | 能联网核实，判断质量最高（推荐） |

没有 key 也能用——第三条路就是为这个留的。三条路写出来的都是同一份 Markdown，存在 `digests/`。

### 需求雷达（左栏「发现」组第一项）

「猜你需要」升级成了可以长期追踪的东西。一条需求不是一个关键词，而是一组条件和底线：

| 字段 | 例子 | 用来干什么 |
| --- | --- | --- |
| 目标 | 提高像素素材（角色、建筑、特效）的制作效率 | 生成检索词、判断"能解决哪一步" |
| 常用软件 | Godot 4.7.2、Aseprite、Photoshop | 判断能不能接进现有流程 |
| 预算 | 尽量免费（开源、MIT/Apache 之类） | 收费项目直接降级或跳过 |
| 设备条件 | Windows 笔记本 + 8GB 显存独显 | 显存、Python、平台能不能跑 |
| 能接受的操作难度 | 点几下拖张图就出结果 | 要命令行/装环境的会被标出来 |
| 试过但不满意 | 手绘法线贴图太慢；3D 高模太重 | 避免推荐你已经走过死路的东西 |

需求雷达不预置任何需求，第一次打开是空的：点「加一条需求」写下自己的，之后随时可以「编辑」或删掉。
上表里的例子只是示范怎么填。

**推荐长什么样**：每条都先过条件，再判断能解决哪一步，理由写成「它能……；但……」——
比如「能对上你说的 sprite、normal、pixel，能批量处理你需要的素材格式、免费（开源）；
但说明里没写怎么用，装之前先看 README 判断要不要碰命令行，它没标明支持什么系统」。

**五个反馈按钮**（有效 / 太复杂 / 太贵 / 不相关 / 已经解决）会真的改下一次的排序：

- 「太贵」≥1 次 → 之后再遇到收费项直接跳过
- 「太复杂」≥1 次 → 要命令行/装环境的跳过
- 「有效」→ 该项目 +6 分
- 「不相关」→ 该项目不再出现
- 「已经解决」→ 这条需求标成已解决，不再参与筛选

**「现在帮我找」**不读旧数据，直接去 GitHub 现搜（由需求关键词生成 ≤2 条查询，`stars:>3` 与
`in:readme stars:>10`），结果同样过条件、同样写理由。**「持续帮我关注」**是追踪名单：
每个 GitHub 仓库每天顺手查一次仓库信息与最新 release，只有这几种变化会被记下来——
出了新版本、加了你要的功能或平台关键词、开放下载/降价、归档或恢复维护、星标跳涨。

**「早期发现」**专门解决"星标门槛会漏掉刚发布的小众项目"：窗口放宽到近一个月、星标 5–1500、
至少两个关键词对上且其中一个是长词（宁可少列，不硬凑）。这一区是「方向对得上、还没被验证」，
和上面按条件筛出来的推荐不是一回事。

**数据时效**：每次都在标题旁写明「数据 2026-10-25」；采集失败、材料还是旧的那天时，
页面顶部会出现一条横幅说明「材料停留在 <日期>」，点「现在帮我找」可以绕开旧数据现搜。

文件：需求存在 `state/profile.json` 的 `needs[]`（和对话共用一个画像），反馈在
`state/feedback.json`，追踪名单在 `state/tracker.json`，采集器每天读 tracker 并在数据里写
`pack.tracked`（简报里是「## Q. 追踪变化」一节）。

### 扩展能力（左栏「扩展能力」）

插件、技能、MCP 放在同一张表里。它们本来分散在各自的软件里，但对使用者来说问题是同一个：
**这玩意儿能帮我干什么，我这台机器能不能用，怎么开始。**

四类用途不是按技术分类，是按「你想干什么」分：

| 用途 | 覆盖的活 |
| --- | --- |
| 通用能力 | 网页阅读、搜索、PDF、表格、翻译、笔记整理、文件处理 |
| 工作专用 | 写作、研究、设计、编程、数据分析、办公自动化 |
| 兴趣专用 | 游戏开发、像素素材、3D、摄影、音乐制作 |
| 连接现有工具 | 让 AI 用你的笔记、文件库、日历或其他服务里的内容（MCP 都在这类） |

数据全部来自机器可读的官方目录，**不靠我手写清单**：

- Obsidian 社区插件（`community-plugins.json`，约 9400 条，按关键词取一批）
- VS Code 市场（`extensionquery` 接口，带装机量，低于 5000 装机的直接滤掉，免得捡到玩笑扩展）
- Godot Asset Library（`asset?filter=…&godot_version=4`）
- Blender 扩展站（4.2+ 的官方扩展接口）
- 官方 MCP Registry（`registry.modelcontextprotocol.io`，取有远程地址或 npm 包的）

**每张卡片回答六件事**：它在哪个软件里用、收不收费、需要什么权限、怎么开始（带可复制命令）、
最近哪一天核实、以及这个结论有多可信。

**三档标记是分开的，不互相冒充**：

| 标记 | 含义 | 怎么来的 |
| --- | --- | --- |
| 目录收录 | 能在官方目录/市场检索到 | 接口返回了这条记录 |
| 作者宣称 | 只有作者自己的说明 | 一般不会单独出现，卡片默认落这一档 |
| 实测过 | 这台机器上真的取到了包或页面 | 点「实测一下」跑一次安全探针，带日期与结论 |

「实测一下」对每一种来源做的都是安全、无副作用的事：VS Code 扩展查市场接口、Obsidian 插件取
`manifest.json`、Godot/Blender 取资源页、MCP 查 Registry 里还在不在。**它只证明「现在还拿得到」，
不证明「装上一定好用」**——这句话也写在卡片上，避免把"能下载"读成"能用"。

**权限一栏要诚实**：这些目录接口基本不给权限清单，所以卡片写的是由形态决定的通用事实
（比如 Obsidian 插件"能读写你的 vault"、MCP「需要这些凭据：<环境变量名>」），作者没声明的都标「未标注」。

**MCP 是什么**：让 AI 连接其他工具的接口——它不是插件，得有兼容客户端（Claude Code / Codex 这类）才连得上，
所以卡片上写着「先装宿主」。

**按环境筛选**：顶部先告诉你这台机器上装了哪些宿主（VS Code / Obsidian / Godot / Blender / MCP 客户端），
没装的宿主，对应卡片标「还没装」；点「只看本机能用」就只留现在就能装的。

目录缓存在 `state/exthub.json`（12 小时，别每次开页面都去问五个站），点「刷新目录」强制重取。
卡片的标题与描述也进了 `Ctrl+K` 索引，搜「obsidian dataview」能直接跳到那张卡片。

取数与分类都在 `exthub.mjs`（零依赖 ESM）：要加一个新来源，写一个 `fetchXxx()` 返回卡片数组，
再往 `SOURCES` 里加一行就行；用途分类不准就改 `USE_RULES`（按 connect → hobby → work → general 顺序匹配），
不用动应用其他部分。

### 查找与标记

采集和简报解决「今天看什么」，下面这几件解决「三天后还能不能找回来」：

- **搜索 `Ctrl+K`**（或左栏按钮、或 `/`）—— 一次性搜所有天的仓库名、项目描述、模型 id、新闻标题、
  论文摘要，以及你写过简报的正文（所以"我当时怎么判断的"也能搜到）。多个词用空格分隔＝都要命中；
  全都没命中时自动放宽成"任一词命中"并提示。`↑↓` 选、`Enter` 打开、`Esc` 关。索引来自 `data/*.json`，
  文件变了才重建，几十天量级仍是毫秒。
- **已读** —— 点过任何链接就记「已读」，雷达列表里那一条变灰；顶部筛选可切「全部 / 未读 / 已收藏」。
  记录留在 `state/read.json`，保留 90 天，设置里可一键清空。
- **收藏 ★** —— 每条右边都有，收进「收藏」页（`state/bookmarks.json`）。两者都是纯本地文件，可手改、可备份。
- **项目详情抽屉** —— 点雷达里的仓库名，右侧滑出抽屉：星标历史曲线（来自 `data/*.json` 里每天记录的
  stars，所以**日期越攒越准**，首日只有两个点）、逐日增量、topics、建立时间，以及两个动作：
  「在 GitHub 打开」和「复制「深挖这个项目」指令」——后者把一段带上下文的提问复制给 DSH。
- **键盘**：`j` / `k` 上下走，`o` 打开（仓库进抽屉，其它开链接），`s` 收藏，`/` 搜索，`Esc` 关。 

### 技能栏

雷达里有一栏「技能」，专门收给 agent 用的可复用能力包（`SKILL.md`、rules、prompt pack 一类），
并且**按它作用的 agent 分组**——同一个技能写成 Claude Code 的 `SKILL.md` 还是 Cursor 的 rules，
装法完全不同，混在一起看没有意义。

分组：Claude Code / Codex（ChatGPT）/ Cursor / GitHub Copilot / Gemini CLI / DSH（DeepSeek）/
其它编辑器 agent / 通用 Agent Skills，组内按 ⭐ 倒序。

识别规则在 `skills.mjs`（采集器和应用共用同一份，不会两边漂移）：仓库要带技能信号
（`SKILL.md`、`agent skill`、`skills` 类 topic、名字里带 skill 等），再按名字/描述/topic 里的
agent 关键词归类；同时提到两个 agent 时按上表顺序取靠前的。宁可严一点——普通应用只是描述里
提一句 "skill" 不算。

采集器每天多跑一次 GitHub 搜索（`skills in:name,description,topics`），结果存在
`data/YYYY-MM-DD.json` 的 `github.skills`，并在 `inbox` 的 K 段按 agent 分组列出；
`prompts/daily.md` 里也加了一节，让每天的简报挑 1-3 个「装到我这边能立刻生效」的。

**安装榜**：技能栏最上面那组来自 [skills.sh](https://www.skills.sh/)——跨 agent 的技能市场，
排序不看 GitHub 星星而看**实际安装量**。采集器抓它的首页（Next.js 的 RSC 数据里带
`initialSkills`，600 条技能 / 88 个来源 / 142 个官方），每条带：
累计安装、**本周 vs 上周增量**、是否有官方背书，以及一行 `npx skills add <来源> --skill <id>`。
首页的 `weeklyInstalls` 是最近 8 周的每周安装量（按时间正序），拿来算周增；24h 增量则靠
`state/skills_sh.json` 里昨天存的安装量比出来（同样有 6 小时门槛，防止把短间隔外推成一天）。
每日 `data/*.json` 只留前 150 名并去掉每周明细，否则一天 470KB。

每张卡片上还有一个**「说明书」**按钮：能做什么、本机能不能用、怎么装、装好没、怎么卸——
见下一节。

### 社区（B站 / 知乎）

雷达最后一栏「社区」，和上面几栏的性质不同：**它不是技术事实，是「别人做到哪一步、普通人在怕什么」**。

- **B站**：三个入口合并去重——① 全站热门 50 条 ② 科技分区榜（`ranking/v2?rid=188`，97 条，要 WBI 签名）
  ③ 关键词搜索（老接口 `search/type`，不需要签名）。只留标题命中紧关键词、**90 天内发布**、
  搜索来的还要**播放 ≥ 3000**；「AI MV 大赛 / 全民制作人 / 鬼畜」这类创作赛作品直接过滤。
  关键词池 8 个（本地部署大模型 / ComfyUI 工作流 / Qwen 本地部署 / Stable Diffusion 教程 / Ollama 教程 /
  AI 编程 教程 / LoRA 微调 教程 / 像素画 AI 生成），每天按日期轮换 3 个——同一个词天天搜回来的是同一批视频。
  每条带播放量、作者、分区、来源（热门 / 分区榜 / 搜「xx」），按播放量排。
- **知乎**：取热榜 50 条里跟 AI 沾边的（通常 3-5 条），带热度值。热榜是全网红黑榜，这里只用它看「疑问集中在哪」，
  不当事实引用；`prompts/daily.md` 里明确写了这条纪律。
- 为什么值得看：B站的「本地跑大模型 / 显存 / 量化」类教程是最快能照着做的中文材料，播放量说明它真的被人看懂了；
  知乎热榜能看出普通人对 AI 的情绪拐点（例如「AI 写代码太快，要不要放弃 Review」）。

数据进 `data/*.json` 的 `bilibili.items` / `zhihu.items`，也进 `inbox` 的 M / N 段、Ctrl+K 搜索、
对话材料（模型能引用「B站上别人怎么部署的」）。采集器对这两个源也走「源挂了沿用上一份」的保护。

### 联网搜索（Bing RSS）

情报系统的「联网」不是让模型随便上网，而是**给它一份刚搜出来的材料**，出处可点。三处用到：

| 位置 | 做什么 |
| --- | --- |
| 采集器 `web` 源 | 每天用**当天新上架的两个模型名**当查询词（例如「Kimi K3.1 Pro 实测」），把中文实测、二手转述抓进 `data/*.json` 的 `web.items`，进 inbox 的 O 段 |
| 对话 | 每问一句，先拿这句话去搜（能用就带上结果，5 条），结果拼进 system 的 `<联网搜索>` 段，回答下面列出域名 |
| 搜索浮层 `Ctrl+K` | 底部固定一行「在网络上搜「q」」，点一下把网页结果混进本机搜索结果里 |

**为什么是 Bing RSS**：本机 DuckDuckGo、Brave、Google 全都连不上（curl 直接 000）；`cn.bing.com/search?q=…&format=rss`
是标准 RSS（10 条，带 title/link/description/pubDate），不用解析 HTML，也不怕页面改版。

**为什么查询词要"具体"**：Bing 对泛词只会返回官网首页。实测「Claude 新模型 发布」全是 claude.com 首页，
而「Kimi K3.1 Pro 实测」能拿到 36kr、爱范儿、网易、B站评测。所以：

- 采集器的查询词从**当天 OpenRouter 新上架模型名**生成（`webQueries()`），不是固定词表；
- 对话里会先把人话压一遍（去掉「请问/帮我/吗/呢」），整句搜不到就退到只留带英文数字的那几个词（`webQueriesFromText()`）；
- `websearch.mjs` 的 `rankResults()` 按「像不像一篇文章」重排：文章站点 +3、路径带 `/article|/p/|.html` +2、
  标题里有「发布/上线/实测/评测」+2，`/signin`、`/download`、官网首页路径直接扣到出局。

两个开关：设置页「联网搜索」，或对话输入框下面那个「🔎 联网」。关掉就只用本机采集的材料——更快、更便宜，
但新发布的东西它确实不知道（回答里也不会出现来源行）。

成本与失败：一次搜索约 1 秒、不花 token，结果缓存 10 分钟（`WEB_CACHE`）。搜索失败不影响回答——
`chatWebHits()` 捕获后返回空数组，模型照常用本机材料答；`web:search` 出错时会把网络错误翻成中文
（超时 / 被挡 / 连不上）。采集器里 `web` 源同样受「挂了沿用上一份」保护。

### 翻译（并入雷达，不再是单独栏目）

中英双向，入口都在读的地方，不用切页：

- **行内「中」** —— 雷达每条英文标题/简介右边点一下，下面多出一行中文（同一按钮再点切回原文）；
- **「译这一栏」** —— 雷达筛选条上，把当前标签页里还没翻的前 8 条一次译掉（逐条请求，失败不会连累后面的）；
- **简报「译成英文」** —— 今日简报底部，整篇翻成英文；
- **长文** —— 设置里的「翻译长文」还留着纯文本框版本，粘一篇文章进来翻。

| 细节 | 做法 |
| --- | --- |
| 分块 | 按空行切，每块 ≤1500 字符；长文分多次请求再拼回，避免一次超长被截断 |
| 缓存 | `state/trans.json`，key = `方向:sha1(去多余空白的文本).slice(0,16)`，上限 4000 条；命中直接返回，`cached:true` |
| 保结构 | prompt 明确要求保留 Markdown、代码块、命令、链接、专有名词，只输出译文 |
| 没 key | 返回 `{ok:false,needKey:true}`，界面提示去设置填一个，不会静默失败 |

### 前沿动态（雷达第一栏：AI 又能做什么了）

回答的是「**又能做什么了**」，不是「又发了什么」。三层，都在同一个标签页里：

| 层 | 内容 | 怎么来的 |
| --- | --- | --- |
| 今天值得知道 | 最多 5 条，白话一句说清发生了什么 | HF Daily Papers 里按 `signal` 排，优先 3 天内 |
| 本周能力变化 | 哪些事更便宜了、上下文更长了、本地能跑了 | 模型价格/上下文快照 diff（`state/models.json`）+ Ollama 新模型 |
| 深入了解 | 论文 / 代码 / 演示 / 评测，按「能做到哪一步」排 | 全部 24 条，按状态分组 |

每条都标状态，从弱到强：**论文提出 → 已有演示 → 有开源实现 → 开放测试 → 正式可用**。
判定是规则化的，不是模型猜的：有 `githubRepo` → 有开源实现；只有 `projectPage`/视频 → 已有演示；
标题或摘要里有 beta/preview/waitlist/内测 → 开放测试；标题命中当天新上架模型名 → 正式可用。

排序权重 `signal = upvotes + (有代码 ?12) + (有演示 ?6) + (星数≥100 ?8)`——**热度只作参考**：
HF 的点赞是「多少人收藏了」，不等于效果好，所以有代码/演示的会被顶上来。这一条也写进了 `prompts/daily.md`。

还有一块「**和你现在做的事无关，但值得知道**」：拿 `state/profile.json` 里的需求关键词做反筛，
专门留几条对不上的——对不上才有可能是新用途。没记需求时退化成「今天热度最高、但没进今天值得知道」的几条。

来源：`huggingface.co` 本机直连不通（000），走 `hf-mirror.com/api/daily_papers` 镜像（同一个 API）。
HF 页面链接仍是 `huggingface.co/papers/<id>`，打开需要你自己能访问 HF。

### 这对我有什么用（雷达每行的「有什么用」）

安装量、星标、价格这些数字，回答不了「跟我有关系吗」。所以每条都带一个四问卡（右侧抽屉，`#ucard`）：

1. **发生了什么** —— 只写材料里有的事实；
2. **对哪些人有用** —— 具体到岗位或场景，不写「所有人」；
3. **我现在能否使用** —— 四枚 chip：费用 / 门槛 / 中文 / 条件，缺的写「未标注」，不猜；
4. **从哪里开始** —— 今天就能做的一个动作。

两个按钮：「试试看」和「关注后续」。

- **试试看**：`TPL_MATCH` 按标题/描述里的关键词把这条资讯对到一个模板上（周报、读懂一篇文章、改简历、会议记录、学习计划、看懂报错、给外行讲技术、整理资料、写邮件），点一下直接进那个模板的填空页。
- **关注后续**：暂时没有能上手的模板时，把它记进 `state/followups.json`，收藏页会多一节「关注后续」。等它出现可用形态（有教程、有开源实现、能本地跑），周报里会提一句。

**证据分级**（`evidenceOf()`）写在卡片最上面一条，因为「官方说的」「别人试过的」「社区在聊」可信度差很远：

| 类型 | 什么时候出现 | 边界 |
| --- | --- | --- |
| 代码自己跑 | 开源仓库 | 能不能用得看你机器和动手能力 |
| 官方上架信息 | 模型市场记录 | 价格和上下文来自上架字段 |
| 官方宣布 | 厂商域名的新闻 | 厂商自己的说法，没经过第三方验证 |
| 官方实测 / 第三方实测 | 标题/描述里有「实测、上手、评测」 | 真的用过，但仍是别人的结论 |
| 第三方报道 | 其它新闻源 | 转述，细节可能有出入 |
| 社区讨论 | HN、知乎 | 是观点和提问，不是事实核实 |
| 体验分享 | B站 | 作者自己的实践，效果因人而异 |
| 论文原文 | arXiv | 作者自己的实验结论，还没变成产品 |

卡片上还固定写三样东西：原始来源（域名可点）、发布日期、核实时间（`verified`，默认当天）。

没填 API key 时四段不会空着：`guessAudience()` / `guessStart()` 按类别和证据类型给出可用的一两句（例如仓库：「想找现成轮子的人；不写代码、或者只做美术的可以直接跳过」），并在卡片底部注明「没填 API key：上面四段是按采集字段拼的，没做模型总结」。
填了 key 才会走模型（严格 JSON），模型没按 JSON 回答时也不会把兜底文案标成模型总结（`generated:false`）。

### 技能说明书（每张卡片上的「说明书」）

安装量只说明「多少人在用」，回答不了新手真正会问的五个问题。技能栏里每条都多一个「说明书」按钮，
点开是一页五段：

| 你问的 | 面板里给你的 |
| --- | --- |
| 能帮我做什么？ | 作者 `description` 中文摘要，加上他写的成品示例；**作者没给示例就直接说「作者没给」，不编** |
| 我能不能用？ | 结论（本机条件够了 / 能用但差 X / 跑不了），逐条依赖 ✓✗，以及「说明 / 脚本 / 资源」各几个文件 |
| 怎么开始？ | 编号步骤：先补条件 → `npx skills add <仓库> --skill <id>` 一行装 → 或手动放整个目录 → 新开会话 → 一句话验证 |
| 装好了吗？ | 扫四个技能目录，指出装在哪、给「打开文件夹」，再给一句可复制的验证话术 |
| 不想用了？ | 禁用（`SKILL.md` 改名，随时开回来）/ 卸载到回收站（`state/skills_trash`）/ 重跑安装命令回到作者版本 |

**为什么要说「复制说明用不了」**：技能不只是一段提示词。Anthropic 官方对 Skill 的定义是
「一份 `SKILL.md` + 可选脚本 + 可选资源」——`SKILL.md` 里写着什么时候用、怎么做，脚本（`.py`/`.sh`）
和资源（模板、字体、示例文件）在外面。所以：

- 一行装（`npx skills add`）会把整个目录放到 `~/.claude/skills/<id>/`，这是唯一「装好」的形态；
- 光把 `SKILL.md` 复制到聊天框，agent 能看到说明，但跑到「执行 `scripts/xxx.py`」就断了；
- 面板第 2 段里 `copyOnly: true` 的技能（只有一个 SKILL.md、没有脚本）才真的能只靠复制说明用起来，
  这时面板会明说「这个技能只有说明文件，把 SKILL.md 放进技能目录就够了」。

**适配是怎么算的**（`skilldoc.mjs` 的 `analyzeFit()` + 主进程 `probeEnv()`）：

- 检测 Node、Python、git、Docker、bash，以及 claude / codex / gemini / opencode / cursor 装没装；
- 依赖是从 SKILL.md 正文 + 文件清单里读出来的：出现 `.py`/`pip`/`pandas` → 要 Python；出现
  `docker run`/`compose.yml` → 要 Docker；出现 `API_KEY` → 要密钥；出现 `npm`/`.mjs` → 要 Node；
- Python 必须**真跑一次 `python --version` 并匹配到版本号**——Windows 上 `python` 可能只是微软商店的
  占位符，文件存在但跑不起来，这时候面板会说「本机没有」，而不是骗你装好了；
- 缺 Python 或 Docker 判 `跑不了`（这两个补起来成本高），缺别的判 `能用但差 X`。

**SKILL.md 从哪来**（本机 GitHub 直连不通，探测过一圈）：

- 文件清单：`data.jsdelivr.com/v1/packages/gh/<owner>/<repo>@main`（不限流）；
- 正文：`testingcf.jsdelivr.net/gh/…`，其次 gcore / fastly；
- 兜底：`api.github.com/repos/<repo>/contents/<path>`（未登录 60 次/小时，所以结果会缓存在进程里）；
- 目录结构改过的仓库（例如 `mattpocock/skills` 现在把技能放在 `skills/productivity/<id>/`），
  jsDelivr 的清单可能是旧的，取不到时再翻一次 `git/trees?recursive=1` 找到真实路径。

找不到同名目录时面板不硬猜：列出这个仓库里所有 `SKILL.md` 让你点，点哪个读哪个。

### 安装 agent

左栏「安装 agent」是技能栏的配套页：技能按 agent 分组，这一页告诉你**那些 agent 本身怎么装**。
23 个条目、4 组：

| 组 | 是什么 | 例 |
| --- | --- | --- |
| 命令行 agent | 装在终端里，配现有编辑器 | Claude Code / Codex CLI / Gemini CLI / Copilot CLI / Qwen Code / OpenCode / Crush / Amp / Auggie / Continue / Aider / Goose / Kilo CLI / DSH headless |
| 独立编辑器、客户端 | 下载安装包 | Cursor / Windsurf / Zed / Trae |
| VS Code 系插件 | 在现有 VS Code 里加一栏 | Cline / Roo Code / Kilo Code |
| 本地模型运行时 | 给 agent 供货的本地推理 | Ollama / LM Studio |

每条的安装命令都在 `agents.json` 里，页面上一键复制；带官网链接和"需要什么（订阅 / key / Python）"。
每条标注了核实来源与日期：`npm i -g` 类的是 2026-10-25 对着 npm registry 核过版本号的，
PyPI 一条核过 `aider-chat 0.86.2`，桌面客户端是官网下载页可直连；VS Code 扩展 ID 标了「未核实」，
装不上就在市场里搜名字。

`agents.json` 是普通数据文件，不是代码：想加一个 agent、改一条命令，直接编辑它，重开应用即生效。
它同时进了 `Ctrl+K` 索引，所以「claude code」这类词一搜就到。

### 模板库（左栏「模板库」）

首页顶部也有一条「想直接做点事？」的入口，就是这里的同一批模板。

10 个模板，覆盖最常见的事：写周报 / 读懂一篇文章 / 改简历 / 整理会议记录 / 做学习计划 /
写工作邮件 / 看懂报错 / 给外行讲技术 / 面试准备 / 把一堆资料整理成一份。

**每个模板的详情页固定五块**，都在 `templates.json` 里，不是写在代码里：

| 块 | 说明 |
| --- | --- |
| 解决什么问题 | 一句话说清它治哪种拖延或返工 |
| 需要哪些材料 | 你要准备什么，没有也能用示例 |
| 效果示例 | 一段真实的成品样子，先看再填 |
| 适用工具 | 哪些 AI 能用（本应用 / ChatGPT / DeepSeek 都兼容） |
| 作者来源 | 写明来源与授权，不塞来路不明的模板 |

**怎么用**：表单里填三格（基本都是 textarea 和选择芯片）→ 「看拼好的提示词」会实时显示真正要发出去的文字 →
三个动作任选：

- **直接使用** —— 用你填在设置里的 key 在这里生成，流式输出，能点「再短一半 / 正式一些 / 去掉过程只留结果」继续改
- **复制到其他 AI** —— 不花钱，粘到 ChatGPT / DeepSeek 里一样用
- **保存我的版本** —— 存进 `state/mytemplates.json`，在模板库顶部单独列出，可以复制或删除

**「为什么这样问」** 每个模板末尾都有一段，固定四行解释角色、背景、要求、输出格式，
讲清少写哪一段会缺哪块结果——用模板的过程顺便学会自己写。

拼装规则在 `app/main.js` 的 `composePrompt()`：`system` + `templates.json` 顶层 `rules` + 填好 `{{占位符}}` 的 `user`，
末尾再补一句「直接输出成品，不要解释你在做什么」。想改全局口吻就改 `rules`，一处生效于所有模板。

没有材料也能体验：每个 textarea 都有「用示例填一下」。「读懂一篇文章」那个框还能直接填链接，点「抓取正文」
（只认 http/https，20 秒超时，抓不到会告诉你改粘正文——遇到登录墙就是抓不到）。

### 概念词典（左栏「概念词典」）

它按**词典**用，不按长文读：搜一个词 → 打开它单独一页 → `Esc` 或「← 返回」回到刚才那一屏（历史栈记住你从哪儿来）。
69 个核心词分八组，顺序就是建议的读法
（计算机侧 → 工程侧 → 硬件侧 → 多媒体与图形侧 → 模型侧 → AI 用法侧 → 网络与安全侧 → 判断侧）；
页首一排组名带词数，点一下跳到那一组。想一次读完整页，按「展开全部正文（当书读）」。

- 搜索：`/` 或点搜索框，Enter 打开第一条；词条名 > 英文名 > 通俗解释 > 专业解释 > 案例，多词是「都要命中」
- 回退：`Esc`、面包屑前的「← 返回」、词条页里的「回到「领域包」」
- 每个词条页底部有「同一类里的其它词」，横向换词，不回到列表

每个词四层，按「先说准，再说人话，再给例子」排：

- **专业解释** —— 用准确术语讲一遍（偏硬，但这是能拿去跟人对话的版本）
- **通俗解释** —— 说人话的一句，大字衬线，方便记
- **具体案例** —— 真发生过的事，写清型号、数字或命令（不是"比如某个模型"这种糊话）
- **容易搞错** —— 最常见的误解，直接点破

内容全在 `concepts.json`（`pro` / `plain` / `case` / `mistake` 四个字段，`g` 决定它落在哪一组，
`groups` 顶掉组名与顺序），改文件重开即生效；
这些文字同时进 `Ctrl+K` 索引，搜索能落到词条。

#### 领域包：想学一个新领域时用

三个内置领域包（`domains.json`）：**音乐制作**（7 词 / 6 工具）、**游戏美术·像素**（7 词 / 7 工具）、
**数据分析**（7 词 / 4 工具）。每包不是词表，是一份「能照着走」的结构：

| 字段 | 内容 |
| --- | --- |
| `what` / `why` | 这个领域到底在做什么、为什么现在值得学 |
| `level.begin` / `level.useful` | 「从这开始」到「学到这儿算够用」两句话 |
| `path` | 4 步路径，每步有 `detail`（为什么）和 `do`（今晚能动手的一件事） |
| `concepts` | 这个词条组的词，字段与核心词条相同，四层解释 |
| `tools` | 4–7 个工具：干什么、免费与否、官网链接，链接带核实日期 |
| `sites` | 找素材/看别人怎么做的网站 |
| `next` | 有基础之后往哪走 |

**按需生成**：点领域包那一行的「＋ 我要学一个领域」，写「电子音乐混音」「做播客」「3D 角色绑定」这类名字，
模型会现写一份（6–8 词条、4 步路径、4–6 工具、3–4 网站），存进 `state/domains_custom.json`，
之后照常出现在包里、也进搜索。生成时**每个工具和网站链接都会真的去 HEAD 一次**：
能打开记核实日期，打不开就明确标「链接打不开，别当它还在」或「这天打不开」——不假装有效。
因此生成要 20–40 秒，且必须有 API key。

为什么先放计算机侧：不懂「路径」「命令行」「密钥」「状态码」这四个词，后面 AI 的部分全是雾——
报错看不懂、命令不敢粘、Key 不知道怎么填，卡的都是这些。

为什么加工程侧：一旦你开始用 agent 干活，「前端 / 后端 / 数据库 / 部署 / 日志」这几个词会反复出现——
给 agent 描述项目要分清「界面」和「数据」，看报错要知道去翻日志而不是靠猜，部署决定它是每天自己跑
还是你手动点。这一组都配了本项目的真实例子（`app/renderer` 是前端、`app/main.js` 是后端、
`data/*.json` 是数据库、Windows 计划任务是部署、`logs/collect.log` 是日志），读完能跟自己会的东西对上。

另外四组各有明确用途：

- **硬件侧**（5）—— 回答「这台机器能不能跑」。8GB 显存是常见的分界线：8B 按 q4 约 4–5GB，
  再留 1–2GB 给上下文；跑分前先插电，电池模式下性能能差一倍。
- **多媒体与图形侧**（6）—— 像素美术与光照的落点：整数倍缩放、锁色板、硬边/羽化怎么分、
  图集与十二帧动画、法线贴图（2D 光照的死结）、按 delta 推帧而不是按帧数。
- **AI 用法侧**（7）—— 从「会聊」到「能稳定干活」：给样例、要 JSON、压上下文、把稳定内容放前面吃提示缓存、
  先提示再检索最后微调、按总成本而不是单价选模型、结论必须能点开核对。
- **网络与安全侧**（9）—— 出事时最贵的部分：从右往左读域名、没有小锁别填 key、Cookie 是登录态、
  代理影响的是出口不是有没有网、`127.0.0.1` 与 `0.0.0.0` 的区别、别所有命令都用管理员跑、
  key 泄露了要换锁不是删照片、依赖越少被投毒的面越小、备份要能恢复才算备份。
