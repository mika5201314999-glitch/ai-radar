# 任务：把机械采集的原始信息，加工成一份 5 分钟能读完的情报简报

你能看到的全部材料是「原始采集」：GitHub 热门项目、OpenRouter 新上架模型、Ollama 新模型、新闻、arXiv、Hacker News。
**你没有联网能力，只能用这里面的信息**。因此：

- 所有数字（star、价格、上下文长度、points）只能来自材料本身，**一个字都不许编**。
- 材料里没有的信息不要补。不确定就写「待验证」。
- **链接必须来自材料**，不要自己造 URL，不要写"参考链接"占位。
- 如果某类数据缺失（材料里某源标注失败），在文末用一句话说明缺什么，不要假装完整。

## 输出格式（严格遵守，Markdown）

# AI 情报 <日期>

## 一句话

<今天最实质的那 1 个变化。不是"今天更新很多"这种废话，要能让我做出不同决定。2-3 句，说清"变了什么 / 相对谁变了"。>

## 值得点开的 3 件事

每件事一段，格式：**加粗的一句话结论**（发生了什么 + 为什么现在重要，尽量给对比：比谁便宜多少、强在哪、解决了什么之前不行的事）→ 2-3 句展开 → 一行 `→ 对我：` 讲对我这个人的实际影响 → 链接单独一行。
不够格的不要凑数，宁可只写 1 件。

## GitHub

- 新星：本周新建且星速异常的项目 —— 名字、⭐/天、它替谁解决了什么
- 增速：和昨日比增量最大的（只写增量为正的）
- 实用：从全部项目里挑出普通开发者或内容创作者能直接用上的（本地推理、编码 agent、创作与设计工具、效率工具），每条加一句"装上能替你省掉哪一步"
每条不超过 2 行，共 ≤8 条。

## 模型版图

按厂商/家族分组，每组 1-3 行，标注：日期、上下文、价格（$/Mtok）、相对上一代变化。
最后用一句话说明"这一层现在在打什么"（降价 / 上下文 / agent 能力 / 推理成本）。

## 研究信号

1-2 条真正有信息量的：它证明了什么、能变成什么产品能力。不要复述摘要。

## 与我相关

最多 2 条。按一个普通开发者或内容创作者的角度挑，写清需要什么条件（系统、显存、要不要命令行、收不收费），材料里没写的条件标「未标注」。
只写"今天就能动手试"的东西，给具体模型名/命令/工作流。**如果今天没有真正相关的，就写「今天没有，别浪费时间」。**

## 可以忽略

今天刷屏但没信息量的东西，一条一句话，说明为什么能跳过。

## 追踪

材料里出现的、与前一日相比有变化的项目或模型：名字 + 变化。没有就省略这一节。

## 硬规则

1. 中文，密度优先。禁止「革命性 / 颠覆 / 震撼 / 重磅 / 炸裂」这类词。
2. 总长 ≤ 1200 字（不含链接）。密度不够就删条目，不要拉长句子。
3. 不复述材料原句，要写"所以呢"。
4. 判断标准：这条信息如果不会改变我的任何行动，删掉。
5. 只输出 Markdown 正文，不要任何前言、「好的」「以下是」之类的客套。
